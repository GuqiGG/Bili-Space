# Bili-Space 设计思路

这份文档记录软件「为什么这样做」：定位、交互原则、架构、插件与安全模型，以及已经被否决、不要再做的方案。改动之前先读一遍；做了新的取舍就补进来。

## 1. 定位

- **你的最后一款 B 站客户端**：保留官网的登录、播放器、弹幕和推荐，不重新发明播放器。我们只做外壳和增强。
- **主打高度自定义**：能让用户自己决定的就做成设置，并且尽量用拖动条、实时预览，而不是写死的几档。外观、顶栏、首页、播放相关的细节都集中在「个性化」里。
- **轻**：C++20 + WebView2，不用 Electron。没有用处的常驻开销都要砍：离屏暂停循环、事件驱动的顶栏、弹幕和直播聊天不触发页面扫描、精简打包。
- **尊重老用户**：每次大改都要让老用户「有感觉」，同时给他们保留原样的选项（例如欢迎引导里的「还是现在好」）。
- **国内外网络都要能用**：不要强制跳 `/zh-Hans` 等语言路由。在海外 IP 下那会打开没有「换一换」的海外版首页（`localeRedirect` 返回空）。

## 2. 交互与视觉原则

- **参考体系**：Apple HIG 风格，克制、内容优先、外壳安静。颜色以中性色为主，只有一个强调色（用户可选），状态色只用于状态。
- **动画**：
  - 只动 `transform` 和 `opacity`（或 filter 这类合成层属性），不动布局。
  - 统一缓动：`cubic-bezier(.32,.72,0,1)`。进入 300–450ms，离开 240–260ms。新的操作会立刻结束上一段动画，不排队。
  - 一定要尊重「减少动态效果」：系统开了就直接切换或只做淡入淡出。
  - 动画结束后要清理保持态（`fill:'forwards'` 的动画要 cancel）。否则往回切换时会留下透明页面，0.1.62 修过一次。
- **一页一事**：引导、对话框都是一屏只有一个焦点、一个主按钮。设置项多就分页，不要一页塞满。
- **选了就生效**：设置和引导里的选项立即应用、实时预览，不需要「保存」按钮。
- **可以退出、可以后退**：任何流程都要能「上一步」和「跳过」。
- **不用 emoji 当图标**：图标风格统一。弹窗只用于需要决定的事。
- **文字**：中文，简短，按钮用动词。更新日志写给用户看：说明好处，不写实现，不用 `**`（日志原样显示在应用内更新弹窗里）。

## 3. 架构

- **Windows 主程序**：`src/main.cpp`（Win10/11 x64，另有 Win7 目标）。由 zig c++ 编译，CMake 也可。
- **WebView2 composition 宿主**：
  - 用 DirectComposition 组合两层视图：顶栏层 `CHROME_VIEW`（`https://www.bilibili.com/__bili_space_chrome__`，透明，负责顶栏、设置、弹窗、引导）和页面层 `CONTENT_VIEW`（B 站页面，可多个标签）。
  - 点击由 `chrome-layout` 上报的矩形和 modal 状态决定落到哪一层。
  - 顶栏层只有报告过的区域能接到点击，其余地方会穿透到网页。凡是在顶栏页面里显示的东西都要报告，包括不在客户端界面里、由别的脚本打开的窗口（登录面板、线程撕裂者设置等）；模态 `<dialog>` 按整窗处理，已关闭的 dialog 要跳过。
  - 视频网页全屏时，左下角的设置、上传悬浮按钮要隐藏，不能挡住播放器控制栏。
  - 文字缩放 = RasterizationScale × Windows「文本大小」(TextScaleFactor)，实时跟随系统设置。
- **客户端脚本 `assets/enhance.js`**：
  - 同一份脚本同时注入两层视图，用 `CHROME_VIEW` 和 `CONTENT_VIEW` 区分。
  - 调用原生功能：`native(type, payload)`。原生调用页面：`executeEverywhere`、`pluginsBroadcast`、`execute`。
  - 设置 `PREFS` 的默认值在 `DEFAULTS`（JS）和 main.cpp 的默认配置里两边都要加，并在原生端做范围校验，例如 `settingsZoom` 80–160、`downloadConnections` 1–512。
- **页面缩放**：用户用 Ctrl+滚轮等方式手动设置的缩放（`manualZoom`）要在调整窗口大小、最大化、全屏、保存设置之后都保留，只有改缩放设置本身才会覆盖它。
- **全屏**：
  - 默认是原生的普通切换。
  - 从最大化窗口进入视频全屏时，先去掉 `WS_MAXIMIZE`，否则任务栏会露出来；退出后再恢复最大化。
  - 「全屏动画」只是**实验性**选项：默认关闭，开启时有警告弹窗。
- **其他平台**：Linux（`src/linux_main.py`）和 macOS（`src/macos_main.mm`）尽量跟随 Windows 的功能，版本号同步。
- **安卓**（`android/`，`scripts/build_android.ps1` 生成 `dist/Bili-Space-<版本>-android.apk`）：WebView 打开电脑版 B 站（桌面 UA、宽视口），注入和 Linux 同一份 `renderer.js`，`window.chrome.webview` 由 JS 接口模拟。客户端自带文件从 APK 里以 `https://bili-space.local/` 提供。软件内更新读 GitHub 最新 Release 里的 `.apk`，下载后交给系统安装器。版本号跟随 `assets/app-info.json`。暂用 debug 签名，换签名会导致无法覆盖安装。
- **Windows 更新方式**：检查到不是强制的新版本就在后台下载并校验，不弹窗。更新说明（`docs/RELEASE-<版本>.md`）标题里写「小更新」的版本，清单带 `silent: true`：下好后什么都不提示，用户自己退出客户端时由更新器在后台安装（不重新打开），下次启动就是新版。其它版本下好后弹「新版本已下载好」：现在重启更新 / 稍后（Esc 也算稍后，退出时安装）/ 忽略此版本。更新器安装期间持有 `Local\BiliSpaceUpdateInstalling`，这时打开客户端会等它装完（最多两分钟）。关机注销时不装。
- **非 Windows 的软件内更新**：都读 GitHub 最新 Release，用 GitHub 记录的 sha256 校验下载。Linux 下载 `-linux.deb`，用 `pkexec apt-get install` 安装后自动重启；macOS 下载 `-macos-universal.zip`，退出后由一个 shell 脚本替换 `.app` 并重新打开（App 所在目录不可写时提示手动更新）；安卓下载 `.apk` 交给系统安装器。发布流程里有安卓任务，Release 会带上 APK。
- **鸿蒙**：鸿蒙 NEXT 需要 DevEco Studio 和 ArkTS 工程，尚未开始；老鸿蒙（2–4）可以直接装安卓 APK。
- **测试**：
  - `npm test` 是 node 单元测试。
  - `Bili-Space.exe --test` 会打开 CDP 端口 9223。它从 `bili-space.local/fixture.html` 启动，需要真实页面的检查要先导航到 bilibili.com。

## 4. 插件与安全

- 插件 API 详见 [PLUGINS.md](PLUGINS.md)，示例见 `docs/examples/`。原则是「整个软件都能被插件控制、加东西」：顶栏按钮、对话框、侧边面板、窗口、播放器、B 站接口、快捷键、定时器、视频信息和字幕等都开放。插件停用时，它注册的一切都要自动清理。
- **完整权限**：插件声明 `@grant native` 并在导入时经用户同意后，可以访问任意网址、读写文件、运行程序、用 DPAPI 加密保存密钥（实现在 `src/plugin_native.hpp`）。
- **防冒充**：
  - 每次运行生成随机 `PLUGIN_TOKEN`，只注入客户端自己的脚本。
  - `postNative` 在页面脚本运行前就捕获好。
  - `BiliSpacePlugins` 对象冻结、不可写。
  - 原生端只接受带正确 token 的插件消息。
  - B 站网页上的脚本不能伪装成插件。
- **防恶意**：
  - 导入和加载时做静态风险扫描（`pluginRisk`），可疑的直接拒绝。
  - 运行时由 `nativeGuard` 拦截危险操作，例如读账号数据、浏览器密码库。
- **顶栏层是特权视图**：任何来自网络的文字（订阅节点名、提示信息等）插入它之前都必须 `escapeHtml`。
- **原生消息处理**：异常不能逃出 WebView2 回调，否则整个程序会退出，所以畸形消息要先拒绝。

## 4.5 反馈

- 入口：托盘菜单「反馈问题…」和 设置 → 关于与更新。
- 字段：类型、内容；邮箱可选，不填开发者就没法回复；系统信息可选，不含账号、Cookie 和浏览记录。
- 发送：客户端原生 `POST https://bili.gvqi.top/feedback`（JSON），服务器转成 ntfy 推送（主题 feedback）给开发者，不发邮件。
- 客户端里不放任何邮箱或推送凭据。反馈次数不限，但每次间隔至少 30 秒：客户端自己限制，服务器按 IP 用同样的 30 秒间隔兜底，没有每日上限。返回 2xx 算成功，429 提示「半分钟后再试」。

## 5. 欢迎引导（0.1.62）

- 新安装（`RUNTIME.firstRun`）显示「欢迎」，升级用户显示「软件大翻新」。只显示一次（`onboardingSeen`），「重置设置」后也不会再弹。
- 流程：
  1. 展示页：官网宣传图和当前首页截图轮播。
  2. 每页设置一项：主题、强调色、字体、动效、顶栏、首页每行、页面缩放、设置字号、页面净化、声音、关闭窗口方式。
  3. 完成页：引导去「个性化」继续细调。
- 引导期间背后整个客户端全模糊：顶栏层用 backdrop-filter，页面层用 `tourBackdrop` 给 body 加 filter。关闭时卡片先淡出，背景再约 1.1 秒慢慢变清晰，露出配好的样子。
- 老用户在跳过的位置看到「还是现在好」，选了就保留全部现有设置。

## 5.5 更新公告

- 每个版本在安装包里带自己的公告（`assets/whats-new/`），离线也能看。
- 新版本第一次启动时弹一次；新安装的用户在欢迎引导结束后再弹。
- 可以用按钮、圆点或左右键翻页，用 ×、Esc 或「知道了」关闭。看过的版本记在 `whatsNewSeen` 里。设置 → 关于与更新可以重新打开。
- 每页高度一致，翻页时窗口不跳。图片区保持 16:9，并按窗口高度缩小。

## 5.6 分享与远程公告

- 分享弹窗：新安装和每个新版本，关掉更新公告后弹一次（`shareSeen`）；设置 → 关于与更新可以随时打开。分享文案写在 main.cpp 里，由客户端写入剪贴板，网页不能借它往剪贴板写任意内容。
- 远程公告：客户端从 `bili.gvqi.top/news` 拉取，原生端先清洗字段和长度再交给顶栏；每条按 id 只显示一次（`newsSeen`）。格式见 [NEWS.md](NEWS.md)。

## 5.7 多语言

- 13 种：简体中文、繁體中文（台灣）、繁體中文（香港）、粵語、English、日本語、한국어、Español、Français、Deutsch、Русский、Português (Brasil)、萌猫语（用猫的视角写的中文，水桶是「一个含有邪恶液体的小桶」，致敬 Minecraft 的 LOLCAT；译文在 `i18n/cat/`）。
- 界面文字仍然用简体中文写在代码里，渲染时由 `assets/i18n/<语言>.json` 翻译（顶栏层的 shadow root 和客户端加到网页上的 `bili-space-*` / `bs-*` 元素），包括 title、aria-label、placeholder。一段文字只有在已知词句覆盖了它所有汉字时才替换，B 站自己的标题、昵称、评论不会被翻一半。不监听整个网页（弹幕会让它很贵）。
- 繁体不能直接简转繁：台湾用 OpenCC s2twp（網路、軟體、影片、滑鼠、預設…），香港用 s2hk 再换香港用词（視窗、載入、設定…），两边都可以在 `i18n/zh-TW.fix.tsv` / `zh-HK.fix.tsv` 里逐条修正。粤语是口语（嘅、咗、唔、喺）。
- 新安装和更新到带多语言的版本后，先弹一次语言选择（预选系统语言），再进欢迎引导和更新公告；之后在 个性化 → 语言 改。托盘菜单跟着变。
- 改了界面文字：`python scripts/i18n_extract.py`（原文只追加，位置不变）→ 在 `i18n/tr/*.tsv` 里补译文（`-` 表示不显示、不翻）→ `python scripts/i18n_build.py`（需要 `pip install opencc-python-reimplemented`，只在开发时用）。

## 5.8 精选（刷视频）

- 对标官方客户端的「精选」：顶栏 首页 后面的 精选（首页加 `#swipe`，代码里仍叫 swipe），推荐来自 `x/web-interface/index/top/feed/rcmd`。滚轮、↑/↓、右侧箭头切换，播完自动下一个，Esc 退出。
- 每个视频是一个同源的完整视频页 iframe，只露出 `#bilibili-player`：清晰度、弹幕发送、全屏都是 B 站自己的。保留上一个、当前和下面两个（第二个在当前视频出画面后、或切过来 600ms 后开始加载，取先到的；四个视频页大约占 1.2GB 内存，所以不再往后多预加载整页），其余换成 about:blank；预加载的页面里 play() 被拦住，所以它们停在 0 秒、没有声音，但会缓冲 10–25 秒。嵌入式播放器（player.bilibili.com）只有 360P，已否决。
- 右下角按钮用视频页工具栏里的官方图标（点赞、投币、收藏、分享），亮起用 B 站蓝。点赞、投币、收藏成功后播放视频页自带的 SVGA 动画（likeBase/coinBase/favBase 从工具栏组件里读，赞数过百、过千换成 like_heart / like_thumb），用的是 iframe 里的 SVGA 播放器，容器必须由 iframe 的 document 创建。长按点赞一圈进度后一键三连，三项都成功再放烟花。
- 超分和补帧在精选里作用于当前这条视频（`enhanceTarget()`：精选打开时取当前 iframe 的 video），换视频时跟着换；画布插在 iframe 里，所以 `.bs-gpu-canvas` 的样式也要带进 iframe。
- 性能：不在屏幕上的视频页加 `.parked`（`content-visibility:hidden`，不渲染），滑进来的那个在动画开始前解除、滑出去的在动画结束后再停；预加载页准备好之后，检查从每 120ms 降到约每 0.5s。盖在视频上的元素不用 `backdrop-filter`（视频每帧都要重新模糊），用不透明度高一点的底色。补帧（RIFE）本身大约占一个核的七成，是功能本身的代价。
- 拖动窗口大小时，预加载的视频页保持原来的像素尺寸，停下 0.35 秒后才跟上，只有当前这条实时跟着变。
- 评论里的图片查看器、弹窗（`bili-photoswipe`、`bili-modal` 等）是挂在 body 上的，精选的 iframe 里要单独放出来。
- 视频页自己的控制栏、发送栏、顶部标题都隐藏，暂停图标放到画面正中；底部一排是 UP 主信息、居中的弹幕输入框（填进页面隐藏的输入框再按它的发送键，弹幕立刻出现）、右侧按钮，最底下一条可拖动的进度条。
- 评论不跳页面：视频页自己的评论区（`#commentapp`）变成从右边滑出的面板，播放器以左边为原点缩小到剩下的宽度（只用 transform），覆盖层同步变窄；面板里滚轮滚评论，视频上滚轮照常切换（切换前先收起面板），Esc 先收面板。
- 评论面板去掉了「评论 N / 最热 最新」那一行，头像贴左、字号放大、字体跟客户端设置（抖音美好体或系统字体）。评论区是层层 shadow root，用一张 constructable stylesheet 采用进每个 shadow root，面板打开时每 0.5 秒补一次新渲染出来的。
- 展开简介：信息块高度从下往上长（0.42s，和切换视频同一条缓动），简介晚 90ms 淡入上浮，箭头同步转；收起倒着放，箭头立刻转回。
- 点画面暂停由精选自己处理（在 iframe 的 document 上捕获 click），播放器自己的单击要等双击判定，有明显延迟。空格在页面和 iframe 两边都处理；覆盖层按钮鼠标点了不留焦点，免得空格又按一次它。
- 覆盖层 3 秒不动鼠标就淡出（鼠标停在按钮上、弹幕框有焦点、评论打开、长按蓄力时不隐藏），动鼠标出现。最右边的「清屏」按钮（Material Symbols 的 visibility / visibility_off 实心眼睛，按下变成划掉的眼睛；文字颜文字、旋转 90° 的脸、画的 :3 都被否决了）隐藏除它以外的全部，再按一次才恢复。
- `#bs-swipe` 用 `overflow:clip`：hidden 仍能被 scrollIntoView / focus 滚动，会把整个覆盖层顶上去。
- 点赞、投币、收藏、关注先在界面上生效（数字跟着变、动画立刻播），请求在后台发，失败再改回来并提示。
- 顶栏是否收起跟着当前标签页的路由走：点评论、详情页打开视频标签页时顶栏自动回来，切回刷视频再收起。
- 刷视频时顶栏收起，视频铺满窗口。鼠标碰到顶部中间的小横条（或最上沿）时顶栏滑下来，离开顶栏且没有打开的搜索框、菜单时再收起。

## 5.9 去掉浏览器自己的界面

- 右键：只有在输入框或选中文字上才弹菜单，并且只留表情、撤销/重做、剪切/复制/粘贴/全选；其它地方右键什么都不弹（网页自己的右键菜单，比如播放器的，照常）。
- 下载：网页发起的下载不弹 Edge 的下载气泡和下载记录卡片，完成或失败时顶栏提示一句。
- 只打开浏览器界面的快捷键（Ctrl+F 查找栏、Ctrl+P 打印、Ctrl+S 另存为、Ctrl+U 源代码、Ctrl+J/H、F3、F7 光标浏览，正式版里的 F12 和 Ctrl+Shift+I/J/C）不起作用；触控板左右滑动返回的浏览器箭头关掉了，地址/表单自动填充和密码保存提示也关掉了。

## 5.10 评论屏蔽

- 设置 → 页面净化 → 评论屏蔽：用户名一行一个（昵称完全一致），屏蔽词一行一个（评论里出现就屏蔽），楼中楼回复也会过滤。视频页每 0.8 秒检查一次评论区（名单为空时不检查），精选的评论面板也一样。评论数据从 B 站评论组件自带的 `data`（`member.uname`、`content.message`）读。

## 5.11 拖动窗口大小

- 拖动卡顿的主因：`applyUiScale` 按宽度算的界面缩放精确到 0.001，几乎每步都会改根元素上的 CSS 变量，整页样式重算加重排（首页几千个元素，两层页面都有）。现在缩放按 0.02 一档，且窗口尺寸停下 150ms 后才改。
- 原生：拖动边缘时网页区域的尺寸最多每 50ms 跟一次，松手时对齐最终尺寸；顶栏每步都跟。测试版每次拖完在日志写一行 `drag stats`（尺寸变化次数、两次之间最长等待、调整网页尺寸的耗时）。
- 精选打开时，下面的首页 `body` 是 `display:none`（关掉时恢复滚动位置），首页卡片整理也不跑：被盖住的几百张卡片原来每拖一步都要重新排版，B 站首页脚本的 `getBoundingClientRect`/`clientWidth` 测量会逼它同步排版。`content-visibility:hidden` 试过，反而让这些测量更贵。
- 首页卡片的整理（`compactHomeFeed`）和唤醒 B 站自己的滚动处理与窗口大小无关，拖动时每一步都跑会让拖动一卡一卡；现在等尺寸停止变化 0.18 秒后才跑一次。

## 5.12 UP 主更新通知

- 顶栏那一层（一直在、已登录）每 4 分钟查一次关注动态里的视频（`x/polymer/web-dynamic/v1/feed/all?type=video`），比上次看到的最新发布时间还新、且是 6 小时内发的，就交给原生弹窗；第一次查只记基线，不弹。基线按账号存在顶栏页面的 localStorage。
- 弹窗（`src/up_notify.hpp` + `assets/up-notify.html`）是独立的小 WebView2 窗口，在客户端所在显示器的工作区右下角（不是窗口右下角），置顶、不抢焦点，从屏幕右边缘滑入、滑出。最多三条，每条「xxx 更新啦！」+ 封面（角上头像）+ 标题，按钮「不看」和随机的「冲冲冲！/抢前排！/走走走！」（打开视频）。12 秒没碰自动收起，鼠标停在上面时不收。原生会再校验一遍内容：只收 BV 号、纯文本和 hdslb 图片地址。
- 开关：设置 → 个性化 → 通知 → UP 主更新通知（`upNotify`，默认开）。
- 弹窗的 WebView 是在窗口隐藏时建的，窗口显示后必须 `put_IsVisible` 一次并 `NotifyParentWindowPositionChanged`，否则屏幕上只有窗口底色、点不动（0.1.67 的 bug）。验证弹窗要截屏幕像素，CDP 截图只是网页内部的画面，看不出这个问题。

## 5.13 关注动态卡片

- 设置 → 个性化 → 动态 → 关注动态卡片（`dynamicCards`，默认开）。动态页（t.bilibili.com）的列表变成卡片网格（每列至少 300px，窗口越宽列越多，同一行等高），右边热搜栏收起，主区铺开。头像缩小放在卡片左上角，视频动态改成封面在上、标题和播放数在下，图片最高 280px，正文最多 4 行。
- B 站给 `.bili-dyn-item` 写死了 `width:556px` 和 `min-width:556px`，里面的内容区、视频卡也是固定宽度，卡片里这些都要改成 `width:auto; min-width:0`，否则会撑出格子。

## 5.14 视频线路（CDN 选择）

- 设置 → 扩展插件 → 线程撕裂者下面的「视频线路」：自动 · 大陆节点（默认）/ 自动 · 海外节点 / 指定节点。不另写一套 CDN 改写：线程撕裂者本来就多 CDN 并发下载，这里只改它自己的设置（GM `sync` 里的 `mode` 和 `customHosts`），节点列表就是它认识的那 13 个。
- 测速：每个节点请求根地址 3 次取最快一次（服务器不需要视频就会马上回应），作为打开视频前能拿到的延迟。「选最快的 3 个」直接写进 `customHosts`。改动对之后打开的视频生效。精选里的视频页是 iframe，线程撕裂者不注入那里，所以精选不受这个设置影响。

## 5.15 首页每行视频数

- 列数按页面自己的 CSS 宽度算（`innerWidth`），不按窗口真实宽度。客户端最大化时会把页面缩放到约 1280 CSS px 宽，以前按真实宽度在大屏上会排 7 列塞进 1280px，封面很小、标题字却照常大；Ctrl+滚轮缩放也不会改列数。现在放大页面列数变少、卡片变大，缩小反过来。
- 「首页每行最少视频数」是下限：任何宽度都至少放这么多（窗口窄也不减少），页面够宽、自动列数更多时按自动的来。以前「最少」看着无效，是因为自动列数按真实宽度算、大屏上本来就 7 列，不是下限本身的问题。自动：≤800 两列，≤1100 三列，<1500 四列，<1900 五列，<2300 六列，再宽七列。

## 6. 否决过的方案（不要再做）

- **启动时的屏外窗口 + 从小电视展开的启动动画**：用户觉得难看。保留原来窗口内的启动页。
- **默认全屏防闪烁覆盖层和全屏放大动画**：多轮修复后仍会闪烁，已删除默认路径，只作为实验选项保留。不要再加回默认路径。
- **强制语言路由 `/zh-Hans`**：会丢失「换一换」。
- **会员 / 打赏 / 赞助类彩蛋和入口**：已删除，不要再加。B 站原生的「充电」按钮要保留，不要隐藏。
- **液态玻璃内置插件**：先后试过自己仿写 CSS、把 LiquidGlass 的着色器按尺寸算成位移图、直接用 @ybouane/liquidglass 库。那个库要求玻璃和背景在同一个容器里、每组一个 WebGL 上下文，只能套在少数几组按钮上，用户决定整个删掉。
- **超分、补帧的 ONNX/RIFE/ESPCN 链路**：为了包体和性能已移除。

## 7. 协作约定（给开发助手看）

- 回复和更新日志用中文。
- 提交和 PR 不加 AI 署名或共同作者。
- 只有用户说「发布 / release」时才推送到发布分支 `codex/navigation-accounts-platforms`，因为推送会触发 CI 构建。平时提交只推到工作分支，或者只留在本地。发布成功不用通知，失败才告诉用户。
- 发布步骤：
  1. 在 CMakeLists.txt、assets/app-info.json、package.json、package-lock.json、src/app.rc（两处字符串和逗号形式）、src/app_info.hpp、src/linux_main.py、src/macos_main.mm 里改版本号。
  2. `git mv .github/workflows/platforms-<旧>.yml platforms-<新>.yml`，并替换文件里的版本号。
  3. 写 `docs/RELEASE-<版本>.md`。
  4. 更新公告：改 `assets/whats-new/whats-new.json` 的 `version` 为新版本，并写好每一页（`title`、`text`，`media` 可以是 mp4/webm/gif/png/webp，或者用 `items` 列一组要点）；配图放在同一目录，可以用 `scripts/record_whats_new.py` 从测试窗口录。版本号对不上时公告不会弹出。
  5. 提交信息带 `[release-<版本>]`，推送到 `codex/navigation-accounts-platforms`，等 GitHub 上的构建和发布全部完成。
  6. 发布完成后，把发布分支合并进 master（`git merge --no-ff`），再推送 master。master 是仓库首页显示的分支，发布脚本会往 master 写每个版本的更新清单，所以必须等发布结束再合并；合并时保留 master 上的 `update-site/public/updates/windows-x64.json`。这样首页的源码始终是最新版。
  7. 只改文档、不需要构建的提交，在提交信息里加 `[skip ci]`。

- 测试绝不发送系统级键鼠输入（keybd_event、mouse_event、SetCursorPos），只用 CDP 操作测试窗口。用户在玩游戏时不要弹出测试窗口。
