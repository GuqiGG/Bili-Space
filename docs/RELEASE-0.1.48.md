# Bili-Space 0.1.48

这一版没有新功能：源码回退到 0.1.46，只把版本号前进到 0.1.48。0.1.47 的改动验证没走完，先发一版能用的稳定内容，保证客户端检查更新后拿到的包是能下载、能装、能跑的。

- 源码回退到 0.1.46，行为与 0.1.46 完全一致：弹幕断档回退原生层、下载线程上限 128、设置页签滚动、本地插件接口都在。
- 已装 0.1.47 的用户直接覆盖安装即可，登录与设置保存在用户数据目录，不会被覆盖。
- 原先计划随 0.1.47 发布的浮动登录面板、顶部栏重构、「每行最少几个」列数设置与默认窗口尺寸调整推迟，修好后再发。

## 0.1.47 为什么推迟

0.1.47 改动集中在登录面板、顶部栏和首页列数三块，验证没有走完就打了包，装上去会出问题。与其把用户留在「提示有新版本但装不上或装上不对」的状态，这一版先把源码退回到 0.1.46，让更新链路恢复正常。

版本号继续前进到 0.1.48，而不是原地重发 0.1.46，是因为已经检查过 0.1.47 更新的客户端需要收到一个版本号更高的包；更新清单只认更高版本。

那几个功能修好之后会以高于 0.1.48 的版本发布，届时正常检查更新即可，不需要手动处理。

## 安装与更新

安装版：运行 Setup；便携版：完整解压 ZIP 后运行 Bili-Space.exe。已有版本可在客户端内检查更新、下载并安装重启。登录和设置保存在用户数据目录，升级不会丢。

0.1.38 的旧更新器存在退出竞态；若安装重启失败，请先从托盘退出客户端，再运行本版 Setup 覆盖原目录。

## 验证范围

- 源码与 0.1.46 发布提交逐字一致，除版本号外没有任何功能改动。
- `node --check`、`scripts/build.ps1` 构建通过，原生可执行文件的 FileVersion / ProductVersion 实测为 0.1.48。
- 与本版一同发布的 Setup、ZIP 与 `SHA256SUMS.txt` 由同一份源码构建，客户端下载后按字节数与 SHA256 校验。
